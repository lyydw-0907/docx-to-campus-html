# 复杂 MathML 与右侧编号：学校暂存回读验证

日期：2026-10-04；时区：Asia/Shanghai。范围是华中农业大学进展检查页面中的合成测试内容。原始 HTML 的结构和编号布局保留，但 5 个数学减号在回读内容中变成问号，语义验证失败。将这些减号规范化为 ASCII `-` 的版本，经另一个独立草稿暂存、编辑页及详情页回读后，10 个公式的数学字符、结构和原编号均符合该修正版的预期。两个测试草稿均已删除，列表恢复为 0 条；没有覆盖已有材料或正式提交。

该学校实验进行时，主产品尚未接入 MathML。后续已接入本地转换器及界面、API、CLI，包括运算符减号规范化和原编号三列布局；界面默认 MathML/14 px，API/CLI 默认仍为 PNG、可显式选择 MathML。产品输出的 10 个复杂公式已在本地与本报告的学校兼容样例完整数学树逐项一致，并通过实际界面复制、下载与格式切换验收；本次没有新增学校请求，每份输出的 `verification` 仍为 `unverified`。用法及本地证据见 [README](../README.md) 和 [验证记录](verification.md)。本报告的学校回读结果只支持所测页面、浏览器、样例和布局，不保证任意新文档兼容。

## 原生 Word 输入与本地转换

合成的 `advanced.docx` 含 10 个 Word 原生 OMML 公式：8 个独立公式、2 个行内公式。Pandoc 3.6.4 使用 `--from=docx --to=html5 --mathml` 实际转换，输出 10 个 MathML 公式，没有转换警告。HTML 不含公式图片或数学脚本；显示依赖浏览器原生 MathML。

| 样例 | 内容 | 核查的数学结构 | 原编号 | 原始学校回读中的字符问题 |
| --- | --- | --- | --- | --- |
| 01 | 嵌套分式 | 两层 `mfrac` | （2） | 未发现 |
| 02 | 二次方程根式 | 分式、根号、平方与下标 | （3） | 2 个减号变为问号 |
| 03 | 定积分及上下限 | 积分限与平方 | （4） | 未发现 |
| 04 | 带括号的 2×2 矩阵 | 2 行、4 个数学单元格及括号 | （5） | 未发现 |
| 05 | 分段函数 | 大括号、2 行条件及平方 | （6） | 1 个减号变为问号 |
| 06 | 上下标同现 | `msubsup`、下标与上标 | （7） | 未发现 |
| 07 | 向量重音 | `mover` 重音箭头及下标 | （8） | 未发现 |
| 08 | 求和、分式与括号组合 | 两个分式、求和上下限及平方 | （9） | 2 个减号变为问号 |
| 09 | 行内分式 | 分式及下标 | 无 | 未发现 |
| 10 | 嵌套普通表格中的行内根式 | 根号及两个平方 | 无 | 未发现 |

独立公式使用三列无边框表格，`table-layout: fixed`，列宽为 10% / 80% / 10%。左侧留空，公式在中列居中，原编号在右列靠右；左右列等宽，使公式中心不随编号宽度移动。表格及单元格 `border: 0`、`padding: 0`，单元格垂直居中，公式字号为 14 px。不自动新增或改写原编号。

## 原始版本：结构保留，语义失败

原始版本通过学校真实源码模式插入，在新建独立草稿中暂存。新增请求 `IsCache=true`，响应 `Success=true`。Modify 编辑页与 Detail 详情页均保留 10 个 MathML 公式、数学结构、8 个原编号及布局样式。

逐字符回读发现，数学显示叶节点中的 5 个 `−`（U+2212）已成为 `?`（U+003F）：二次方程根式 2 处、分段函数 1 处、求和组合公式 2 处。这是保存后 HTML 中的字符变化，不能解释成字体显示差异。公式数量和结构节点不变不足以证明公式语义正确；原始版本不能记为“10 项通过”。

这些样例中的 ±、≥、求和符号、积分符号、向量箭头和希腊字母保留；本次没有取得完整字符白名单，也没有确定字符变化发生在后台哪一环节。

原始测试草稿精确删除，`Remove` 返回 `Success=true`；页面刷新后又独立刷新，确认该草稿消失，列表为 0 条。

## 兼容版本：减号规范化与再次回读

保留原始 HTML 及失败证据，另生成兼容版本：

- 只在 MathML 的显示叶节点中，将上述 5 个 U+2212 改成字面 ASCII `-`（U+002D）。
- 两处单目减号原处于 `mi`，改为运算符 `mo`；其余三处保留 `mo`。不使用 HTML 实体绕过方案。
- 10 条原始 TeX `annotation` 保持不变；其余数学结构和原编号保持不变。

兼容版本另建独立草稿，经实际界面暂存，新增请求仍为 `IsCache=true`，响应 `Success=true`。Modify 与 Detail 回读分别以兼容版本保存前的 HTML 为基准，逐项比对每个数学显示叶节点的路径、标签、命名空间、文本和 Unicode 码点，10 个样例全部一致。10 条原始 TeX annotation 也逐条完全一致，没有减号变成问号或其他数学字符变化；数学结构及原编号保留。

这次比对覆盖样例中的全部显示叶节点，不只统计 `math`、`mfrac` 或减号数量。截图另外核查减号、根号、矩阵、分段函数、向量、积分和求和限的显示。字符回读与视觉检查均满足兼容版本预期，但 U+002D 与 U+2212 是不同源字符，字形也有差异；不能宣称像素无损还原 Word。

## 编号与排版结果

两个版本在学校回读页面中的 8 个独立公式编号均与公式同一行、位于右侧。兼容版本的测量结果为：

| 检查项 | 所测 8 个独立公式的结果 |
| --- | --- |
| 数学可见内容中心与表格中心偏差 | 不超过 0.011 CSS px |
| 编号与公式垂直中心偏差 | 不超过 0.506 CSS px |
| 左右侧列宽差 | 不超过 0.011 CSS px |
| 公式字号 | 14 px |
| 布局与边框 | `fixed`、表格及单元格 0 边框保留；0 padding 保留 |
| 容纳与重叠 | 所测公式均位于中列内，没有与编号重叠 |

这只验证当前容器宽度及样例宽度下的布局，没有验证超宽公式、窄屏换行或自动缩放。

## 草稿状态、请求范围与清理

原始轮与兼容轮各执行一次新增暂存和一次精确删除，各 2 次业务写入、各拦截 12 次通知模块 POST。本次复杂公式实验合计 4 次业务写入、24 次通知请求拦截；这组统计不包含此前两个简单公式的草稿实验或未保存临时测试。
