HTML 读取经过包装函数 `FilterXSS`，该函数在存在 `filterXSS` 时才调用它。当前页面没有暴露 `window.filterXSS`；本次未取得后台或闭包内过滤白名单，不能据此宣称标签或样式不会被过滤。一键排版函数在所读源码中暂时关闭。

## 复杂公式与右侧编号

后续独立实验使用真实合成 Word 中的 10 个原生 OMML 公式，经 Pandoc 3.6.4 输出 10 个 MathML 公式、没有转换警告。8 个独立公式覆盖嵌套分式、二次方程根式、定积分上下限、2×2 矩阵、分段函数、上下标同现、向量重音及求和分式组合；另有行内分式和嵌套普通表格中的行内根式。

原始 HTML 暂存后，结构与原编号均保留，但二次方程根式 2 处、分段函数 1 处、求和组合 2 处的 U+2212 数学减号成为 U+003F 问号。原始版本的语义测试失败，不能以 10 个 math 节点和布局正确替代字符核查；未确定后台具体原因。

兼容版本仅将上述 5 个显示叶节点减号改成字面 U+002D，其中两处单目 `mi` 改为运算符 `mo`，保留 10 条原始 TeX annotation。通过另一个独立草稿暂存后，Modify 和 Detail 的 10 个样例逐项通过叶节点路径、标签、命名空间、文本及码点严格比对；原始 TeX annotation、数学结构和原编号均符合修正版保存前预期，没有问号替代。

8 个独立公式采用无边框、无内边距、固定布局的 10% / 80% / 10% 三列表格，保留原编号“（2）”至“（9）”。数学内容中心偏差不超过 0.011 CSS px，编号与公式垂直中心偏差不超过 0.506 CSS px，左右列宽差不超过 0.011 CSS px；字号 14 px，所测公式均容纳于中列、没有编号重叠。截图目视核查数学结构和编号正常。ASCII 减号与原字符的字形有差异，不是像素无损还原。

原始轮和兼容轮各一次新增暂存、一次精确删除。兼容版详情显示暂存、审核未开始；删除响应成功，触发刷新后独立再次刷新，确认草稿消失、列表为 0 条。完成后解除请求保护并释放内存定位信息，没有正式提交。详细失败证据、规范化范围、回读验收和本机证据位置见 [复杂公式报告](mathml-advanced-verification.md)。

## 对转换器的影响

原生数学路径已取得具体样例的暂存回读证据，且原始复杂版本暴露了字符变化：Word → MathML → HTML 需要规范化所测运算符减号，并核查保存后的数学字符。本地产品现已接入 MathML 和减号规范化，PNG 保留为显式备选。主 API 生成的复杂样例在本地与前轮学校兼容样例完整数学树一致；这一致性没有将任意转换文档的学校验证状态改为通过。

1. 嵌入图片版本仅用于本地预览，不能作为此页面的图片导入方式。直接粘贴包含 data URI 的 HTML 会触发上述替换逻辑。
2. MathML 不生成公式图片；普通图片仍需学校上传和真实地址映射。选择 PNG 时，公式也导出为高清图片和明确显示宽高，再通过相同上传映射流程使用。当前转换工具不会自行登录或调用学校上传接口。
3. 保留 img 的 width、height 属性，避免高清图片按自然像素显示为数倍字号。仅保留图片的 CSS 宽高不足以覆盖学校清理 style 的行为。
4. 初始 MathML 样例的编号位于下一行左侧；后续复杂样例已验证同一行右侧编号和公式居中，本地产品已采用该三列布局。2026-10-04 独立实验未覆盖 PNG 公式显示及外围 span 对齐方案；图片基线样式会被学校清除，工具不能仅靠 img 内联样式保证 PNG 行内公式的基线。
5. 不生成全系统“已确认兼容”的声明。当前 mapped 输出只替换真实图片地址，不会凭空增加学校文件中心属性；普通图片导入路径已于 2026-10-06 获用户保存回读确认。

## 2026-10-04 实验未覆盖的范围

初始本地实验用 Pandoc 3.6.4 的 `--mathml` 将合成 Word 的两个原生公式转换成 MathML，在独立 Edge 中原生显示行内分式与独立求和式，无数学脚本或公式图片。实验预览在本机 `output/mathml-native-preview.html`，截图在 `output/playwright/native-mathml.png`，均不加入仓库。当时主产品尚未集成 MathML；后续产品接入的本地验收另见验证记录。这些实验都没有验证 Word 式结构化公式编辑。

不能仅因编辑器没有数学按钮或数学插件，就认定公式只能使用图片。本次证据支持所测原生 MathML 在当前进展检查页面使用，尚未覆盖以下范围：

- 除所测结构之外的后台 HTML 标签、内联样式、内容长度和图片来源规则。
- 所测样例之外的数学结构和字符、超宽公式、其他页面、正式提交后的呈现及学校 Word/PDF 导出；原生显示不等于提供 Word 式结构化公式编辑。
- SVG 文件能否在服务器上传、保存和重新打开后正常显示；目前只确认前端后缀校验允许。
- 未测图片类型、上传响应的完整格式及 `data-path` 等属性的后台必要性；当前版本普通图片导入的保存回读另已获用户确认。
- 已测三列布局在超宽公式或不同容器宽度下的效果，以及所测之外的表格和公式组合。

2026-10-04 独立实验未覆盖图片上传及 PNG 公式回读；2026-10-06，用户确认当前版本学校端发布验证已全部完成。实际上传节点的 `data-path` 等属性是否是后台持久化所必需，不由这些显示验收结果推断；历史实验范围与当前用户验收分别记录。
